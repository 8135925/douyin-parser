抖音视频解析无水印 · 音频转文字

粘贴抖音分享链接，提取标题 / 简介 / 封面 / 无水印视频，支持下载视频、提取音频、音频转文字

设置：解析服务、转写 API Key、识别模型（默认已配置好，通常无需修改）

已默认为你配置好一个在线解析服务，无需任何设置即可直接解析链接。它是本工具自带的 Node 服务（源码见「解析服务」一节），服务端完成「短链跳转 → 取 ttwid → 手机 UA 请求分享页 → 提取 _ROUTER_DATA → playwm 换 play 得无水印地址」。若该服务不可用，可换成你自己的任意解析接口，页面会自动适配常见返回格式。

抖音 CDN 不返回跨域头，浏览器无法直接 fetch 视频字节。已默认指向在线解析服务的中转端点（支持 Range，可拖动播放），因此原片下载、音频提取、转文字都能一键完成。填写或更换「解析接口」时会自动同步带出。

ttwid 来自抖音首页下发的 Cookie，一般长期有效。失效时点「获取新的」自动抓取，或手动粘贴。

支持 App「复制链接」得到的口令文本（自动提取其中的链接）、v.douyin.com 短链、www.douyin.com/video/xxx 长链、iesdouyin.com 分享链接。

📖 使用说明与原理

    
打开方式（按方便程度选）

    
    
      
  • 本机启动（推荐，界面功能最全）：在 douyin-service 目录双击 启动.bat，或命令行 cd douyin-service && node server.js（Node 18+，零依赖），然后访问 http://127.0.0.1:3000。页面与服务同源，解析/播放/下载/转文字全部可用。
    • 
      
  • 直接双击本文件（file://）：页面默认把解析接口指向 http://127.0.0.1:3000，所以只要本机服务在跑，效果与上面相同。想指向自己部署的域名，打开时加 ?origin=https://你的域名（会记住）。
    • 
      
  • 部署到 Vercel：douyin-service/ 已按 Serverless 形态适配完成，部署后访问自己的域名即可，页面自动同源，不用改任何配置。详见下方「部署到 Vercel」。
    • 
    

    
工作方式

    
    
      
  • 输入：粘贴抖音分享口令 / 短链 / 长链，点「解析」。服务端会返回标题、简介、封面、无水印视频地址，以及点赞、评论、转发、收藏等统计数据。
    • 
      
  • 为什么必须有服务端：① 抖音接口不返回跨域头（CORS），浏览器直连读不到响应；② 分享页只对手机 UA + ttwid Cookie 返回完整数据，缺任一项只拿到 32KB 空壳页面；③ 浏览器禁止网页设置 Cookie / Referer / User-Agent 请求头（设了也会被静默剥离）。这三点都是硬限制，纯前端无解。
    • 
    

    
音频提取与视频下载

    
    
      
  • 媒体中转：抖音 CDN 不返回跨域头、浏览器又禁止修改请求头，所以统一经「设置 → 媒体代理」中转取字节（默认指向本机 / 你的解析服务）。拿到的是原始 mp4——既能一键下载原片，也能解码成 16kHz 单声道 WAV 提取音频；
    • 
      
  • 备用直链：部分作品的主播放地址会失效，自动改用接口返回的备用地址重试；
    • 
      
  • 分片下载：云平台（Vercel）单次响应体上限 4.5MB，中转会把响应截成 3MB 分片，页面按 Content-Range 循环取全再拼装，字节级无损；
    • 
      
  • 实在不行：点「下载视频」保存原片后，用任意播放器观看或交给其他转写工具。
    • 
    

    
音频转文字

    
    
      
  • 使用硅基流动 ASR 接口（默认 SenseVoiceSmall，免费），Key 只保存在你自己浏览器的 localStorage 里，不会发送到除硅基流动以外的任何地方。
    • 
    


    

      🔧 解析服务说明与自建方式
      

        
默认服务做什么：接收 /api/parse?url=抖音链接 → 跟随短链跳转拿作品 ID → 请求 iesdouyin.com 首页获取 ttwid Cookie → 以手机 UA + Referer + ttwid 请求分享页 → 从 window._ROUTER_DATA 提取作品数据 → 播放地址 playwm 换成 play 得到无水印直链 → 返回标准 JSON。另外提供 /api/media?url= 媒体中转（带 CORS 与 Range，可播放、可下载原片、可提取音频）。

        
失败会自动重试：分享页偶发只返回空壳，服务端会换新 ttwid 重试最多 3 次；仍失败则多半是作品已删除或设为私密。

        
想自己部署一份？完整 Node 服务源码在项目的 douyin-service/server.js（单文件、零依赖，Node 18+），本地跑 node server.js，或用任意支持 Node 的平台部署，把地址填到「解析接口」＝ https://你的域名/api/parse?url={url}，媒体代理会自动带出 https://你的域名/api/media?url={url}。

      ▲ 部署到 Vercel（含网络连通性注意事项）
      

        
三步上线：① Vercel 导入仓库，Root Directory 填 douyin-service；② 不需要任何环境变量、不需要装依赖（零依赖），直接 Deploy；③ 打开 https://你的域名/api/diag 自检，看到 parse.ok: true 就说明这条链路在你这个部署上是通的。

        
页面无需任何配置：同源部署时页面用 location.origin 自动指向自己的 API，并且不会带 sharecode 之类只在特定托管网关才需要的参数。

        
网络连通性 —— 这是 Vercel 上唯一容易翻车的地方，逐条说明：

        
    
          
  • 区域（首要因素）：已默认 hkg1（香港）。Vercel 默认区域是 iad1（美东华盛顿），从美东访问抖音要绕行太平洋，延迟 300ms+，而且美东云厂商 IP 段更容易被风控。若 hkg1 也被风控，改 vercel.json 里 regions 一行重新部署即可，按 hkg1（香港）→ sin1（新加坡）→ kix1（大阪）→ iad1（美东） 顺序试（Hobby 计划只允许 1 个区域，只能一个个来；区域在部署时定死，运行时改不了）。
    • 
          
  • 出口 IP 被风控：典型表现是 HTTP 200 但只返回约 32KB 的空壳页面（_ROUTER_DATA 里没有 item_list）——看起来像成功，实际没数据，这是最坑的一种失败。服务端的对策是「空 cookie 先探 → 收下分享页自己下发的 ttwid → 带上重发 → 仍拿不到就换 Android UA」，最多 5 轮。
    • 
          
  • 4.5MB 响应体上限（会直接报错的硬限制）：Vercel Serverless 单次响应体最大 4.5MB，而抖音原片常有 3–30MB，整包透传必然 500。媒体中转因此自动把响应截成 3MB 分片，回 Content-Range: bytes 0-3145727/总长，浏览器看到 206 会自动续请求，<video> 播放不受影响；下载侧按分片循环取全再拼装，字节级无损（有 md5 校验测试）。所以「一次下载 = 多次函数调用」是正常的，不是 bug。
    • 
          
  • 函数超时：maxDuration 已设 60 秒（Hobby 上限），解析内部另压一层 25 秒预算，宁可自己返回结构化报错，也不让平台硬杀成前端看不见原因的 504。
    • 
          
  • 冷启动：Serverless 没有常驻进程，每次冷启动都要重新取一次 ttwid（多 0.5–1 秒），所以跨请求 cookie 缓存没意义、已去掉；作为补偿，解析成功时会把 cookie 放进 X-Dy-Cookie 响应头交给前端复用，二次请求可省一次往返。
    • 
        

        
最稳的方案仍是把 douyin-service/ 丢到一台能直连大陆的机器上跑 node server.js——单进程、零依赖。Vercel 版适合「没机器、图省事」的场景。完整部署说明与排错见 douyin-service/README.md；本地部署前可先跑 node dev-vercel.js 模拟 Vercel 环境验证。
